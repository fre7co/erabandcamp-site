# ERA BAND CAMP — лендинг «Зима, Швейцарія, Saas-Grund»

Одна сторінка, яка веде батьків у квіз `https://erabandcamp.ch/quiz/winter-switzerland/`.
Чистий HTML/CSS/JS, без збирача й без бекенду. Мова сайту — українська.

**Живий preview:** https://erabandcamp.a77.ch

### Швидкий старт для програміста

```bash
git clone https://github.com/fre7co/erabandcamp-site.git
cd erabandcamp-site
node scripts/serve.mjs          # http://localhost:8080 (потрібен Node.js 18+)
```

- Сайт — це просто файли: `index.html`, `privacy/index.html`, `assets/`. Збирати нічого не треба.
- `npm install` потрібен лише для скриптів фото/емодзі (`npm run images`, `npm run emoji`) — див. розділ 2.
- Продакшн-деплой (Docker + nginx/Caddy) — розділ 3. Preview на Cloudflare — кінець розділу 3.
- Місця, які часто змінюються, позначені в `index.html` коментарем `<!-- EDIT: ... -->`.

```
index.html               головна (лендинг)
privacy/index.html       політика конфіденційності
robots.txt, sitemap.xml, favicon.ico
assets/style.css         увесь CSS
assets/main.js           увесь JS (UTM у квіз, аналітика, копіювання телефону, нижня панель)
assets/img/              готові фото WebP 800/1600 px, логотипи
assets/fonts/            Unbounded + Manrope (з Google Fonts, лежать на сервері)
assets/og.jpg            картинка для соцмереж 1200×630
assets/photos-raw/       вихідні фото (SOURCES.json — звідки кожне з Google Drive)
assets/brand/            логотипи й патерни з брендбука (на сайт не потрапляють)
scripts/                 build-images.mjs, fetch-fonts.mjs, serve.mjs, screenshots.mjs
Dockerfile, docker-compose.yml, deploy/   деплой (nginx, Caddy)
screenshots/             скріншоти сторінки: 360, 390, 768, 1440 px
reference/draft.html     погоджений чорновик, з якого зроблено сайт
```

**Аналітика.** Поки ID порожні, скрипти Meta і Google не завантажуються зовсім. Коли вставите ID, сайт сам відправлятиме події:
- клік по будь-якій кнопці квізу → Meta `Lead`, GA4 `generate_lead`;
- клік по Telegram / Viber / WhatsApp / телефону / Instagram / email, «Копіювати» → Meta `Contact`, GA4 `contact` (параметр `method` = канал).

**UTM.** Якщо людина прийшла за посиланням з `?utm_source=...&utm_campaign=...` (а також `fbclid`, `gclid`), ці параметри автоматично дописуються до всіх посилань на квіз.

**Емодзі.** Емодзі на сайті — картинки Apple (`assets/emoji/`), тому однакові на iPhone, Android і Windows. Щоб додати нове: просто вставте емодзі в текст `index.html` і запустіть `npm run emoji` — скрипт сам замінить його на картинку й завантажить файл. Щоб змінити вже вставлене: у тегу `<img class="e" … alt="🎄">` поміняйте символ в `alt` і знову `npm run emoji`. Без запуску скрипта емодзі теж покажеться, просто системним шрифтом.
Графіка Apple не має відкритої ліцензії для сайтів. Якщо потрібно без ризику — `EMOJI_SET=twitter FORCE=1 npm run emoji` (Twemoji, CC-BY 4.0; тоді у футері додайте «Emoji: Twemoji, CC-BY 4.0»).

**Фото.** Щоб замінити фото: покладіть файл у `assets/photos-raw/`, у `scripts/build-images.mjs` змініть `src` у потрібному слоті (`hero`, `ski`, `christmas`, `thermal`, `geneva`, `evening`, `team`) і запустіть:

```bash
npm install
npm run images
```

Скрипт перезапише `assets/img/<слот>-800.webp` і `-1600.webp`, `assets/og.jpg`, логотипи й favicon. Назви файлів не змінюються, тож правити HTML не треба. Після заміни фото на живому сайті браузери можуть показувати старе ще до року (кеш), тому для заміни краще давати новим файлам нові імена або дописати `?v=2` у `src`/`srcset`.

## 3. Деплой (для програміста)

Сервер: Linux + Docker, домен `erabandcamp.ch`, зараз там WordPress.

### ⚠️ Перед заміною — обов'язково

1. **Бекап WordPress.** Збережіть файли (`wp-content`, `wp-config.php`) і дамп бази (`mysqldump` / `docker exec <db> mysqldump ...`). Контейнери WordPress не видаляйте — просто перестаньте вести на них головний домен.
2. **Не зламати `/quiz/`.** Квіз — окремий застосунок за адресою `/quiz/winter-switzerland/`, він сам шле заявки в Telegram. Перш ніж перемикати домен, з'ясуйте, **як саме зараз віддається `/quiz/`**:
   - окремий контейнер/порт → проксюйте `/quiz/` туди;
   - сторінка всередині WordPress → WordPress має лишитися працювати на внутрішньому порту, і проксі має вести на нього `/quiz/` **та** `/wp-content/`, `/wp-includes/`, `/wp-json/`, `/wp-admin/admin-ajax.php` (файли й AJAX квізу).
   Після перемикання перевірте: квіз відкривається, тестова заявка доходить у Telegram-групу менеджерів.
3. **Стара політика.** `/privacy-policy/` → 301 на `/privacy/` (уже прописано в `deploy/nginx.conf`; якщо `/privacy-policy/` перехоплює зовнішній проксі — додайте редірект і там).
4. На старому сайті стояв `noindex`. На новому — `index, follow`. Після запуску додайте `https://erabandcamp.ch/sitemap.xml` у Google Search Console.

### Що всередині контейнера

`Dockerfile` — `nginx:alpine`, віддає статику на порту 80. Конфіг `deploy/nginx.conf`:
- gzip;
- `/assets/` — кеш на 1 рік (`immutable`), HTML — `no-cache`;
- красиві URL: `/privacy/` → `privacy/index.html`;
- неіснуючі сторінки → 302 на головну;
- `/privacy-policy/` → 301 `/privacy/`;
- `/quiz/` у цей контейнер потрапляти **не повинен**; якщо потрапить — 502 з підказкою (щоб помилку маршрутизації було видно одразу, а не тихий редірект на головну).

```bash
docker compose up -d --build        # збірка й запуск
curl -I http://127.0.0.1:8088/      # перевірка: 200
docker compose logs -f site
```

Оновлення сайту після змін у файлах: `docker compose up -d --build`.

### Варіант А — за вже наявним reverse proxy (рекомендовано, якщо проксі вже є)

`docker-compose.yml` публікує сайт на `127.0.0.1:8088`. У проксі: `/quiz/` (і, якщо квіз у WordPress, `/wp-*`) — як і раніше, все інше — на `127.0.0.1:8088`.

Приклад для nginx на хості:

```nginx
server {
    listen 443 ssl http2;
    server_name erabandcamp.ch;
    # ssl_certificate ... (як зараз)

    # квіз — як і раніше (підставте поточний upstream)
    location ^~ /quiz/ { proxy_pass http://127.0.0.1:QUIZ_PORT; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    # якщо квіз — сторінка WordPress, розкоментуйте:
    # location ~ ^/(wp-content|wp-includes|wp-json)/ { proxy_pass http://127.0.0.1:WP_PORT; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; }
    # location = /wp-admin/admin-ajax.php           { proxy_pass http://127.0.0.1:WP_PORT; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; }

    # новий лендинг
    location / { proxy_pass http://127.0.0.1:8088; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
}
```

Traefik / nginx-proxy у Docker: приберіть `ports` у `docker-compose.yml`, підключіть контейнер до мережі проксі й задайте правило з **нижчим** пріоритетом, ніж у квізу (наприклад, Traefik: `Host(\`erabandcamp.ch\`)` для сайту і `Host(\`erabandcamp.ch\`) && PathPrefix(\`/quiz\`)` для квізу — довше правило перемагає).

### Варіант Б — самостійно з SSL (якщо проксі немає)

`deploy/docker-compose.ssl.yml` піднімає сайт + Caddy, який сам отримує й оновлює сертифікат Let's Encrypt і робить редірект `www` → без `www`.

1. DNS `erabandcamp.ch` і `www.erabandcamp.ch` → IP сервера; порти 80 і 443 вільні (зупиніть старий проксі/WordPress на цих портах, але не видаляйте).
2. У `deploy/Caddyfile` замініть `host.docker.internal:8081` на реальну адресу квізу (і розкоментуйте рядки `/wp-*`, якщо квіз у WordPress).
3. Запуск:
   ```bash
   docker compose -f deploy/docker-compose.ssl.yml up -d --build
   ```

## 4. Що зроблено й перевірено

- Сторінка зібрана з `reference/draft.html`: та сама структура, палітра й шрифти, тексти скорочені й вичищені від фактів, яких немає в ТЗ (наприклад, «бронювання від 10%», «проживання 10 ночей», «5 днів на схилах», «тільки наша група в будинку»).
- Фото відібрані з Google Drive табору (зимові зміни; переважно EBC 18 ski, Швейцарія). Звідки кожне — `assets/photos-raw/SOURCES.json`.
- Перевірено в headless Chrome на 360, 390, 768 і 1440 px — без горизонтального скролу (скріншоти в `screenshots/`).
- Lighthouse 12 (mobile, локальний сервер `scripts/serve.mjs` з gzip і кешем, як у nginx): **Performance 97, Accessibility 100, Best Practices 100, SEO 100**; LCP 2.5 с, CLS 0, TBT 0 мс.
- Аудит читабельності: рамка фокусу лаймова на синьому/темному і синя на світлому (рожева на синьому мала контраст 2.8:1); лаймові кнопки на білому отримали темну обводку; чіткіші кнопки месенджерів і картки FAQ; `color-scheme: only light`, щоб Samsung Internet / Chrome не перефарбовували сайт у темному режимі; hover-ефекти лише на пристроях з мишею; службовий текст ≥ 15–16 px; фото терм світліше, Женева насиченіша. На живому домені цифри залежать від сервера — перевірте після запуску.
- Перший екран на телефонах: фото, заголовок і кнопка видні без прокрутки на 360×640, 375×667, 390×664 (Safari), 390×720 (Instagram), 430×760 і на iPad 768×950. Перевірка: `node scripts/fold-check.mjs` (знімки `screenshots/fold-*.png`). На телефоні картки «Що чекає на дитину» гортаються вбік, пункти безпеки — компактні рядки.
- Перевірено в браузері: UTM і `fbclid`/`gclid` дописуються до всіх 6 кнопок квізу, сторонні параметри — ні; шрифти з кирилицею вантажаться; помилок у консолі немає; скрипти Meta/Google при порожніх ID не вантажаться.
- **Не перевірено:** Docker-збірка й `nginx -t` (на машині розробки немає Docker) — перевірте першою командою на сервері: `docker compose build && docker run --rm erabandcamp-site nginx -t`. Події Pixel/GA4 — після того, як будуть ID.
